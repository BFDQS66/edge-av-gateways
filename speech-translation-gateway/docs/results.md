# Ubuntu 虚拟机实测基线

测试环境：Ubuntu 24.04 x86_64，4 vCPU，约 3.8 GiB RAM；sherpa-onnx `v1.13.8`。以下是 2026-10-15 在这台 VM 上的结果。磁盘模型目录约：SenseVoice 230 MiB、Kokoro 207 MiB、Piper 中文 63 MiB、Piper 英文 79 MiB，另有运行时与下载归档。速度和内存均不是 RK3588 预测。

## FLEURS 开发集上的识别对照

公开的 [FLEURS](https://huggingface.co/datasets/google/fleurs) 开发集固定到 Git 修订 `4683b04af03d2d9549064c7d72060a9a94bb6046`。脚本从每种语言的开发集等间距选出 100 条，转成 16 kHz 单声道 PCM16 后通过常驻服务识别。英文有 1 条长 31.74 秒，超过服务的 30 秒上限，因此有效样本为 99 条。计算时去掉标点、空格并做 NFKC/小写归一化；中英文混说的拉丁字母仍计入中文字符错误。此口径便于同批配置对比，不能直接与其他论文分数比较。

| 模型与策略 | 中文 CER（3613 参考字符） | 英文 WER（2044 参考词） |
| --- | ---: | ---: |
| SenseVoice，VAD 切段识别，ITN 开 | 266/3613 = 7.36% | 258/2044 = 12.62% |
| SenseVoice，VAD 仅门控、识别整段，ITN 开 | **254/3613 = 7.03%** | **192/2044 = 9.39%** |
| SenseVoice，不用 VAD，ITN 开 | 254/3613 = 7.03% | 192/2044 = 9.39% |
| SenseVoice，VAD 仅门控、识别整段，ITN 关 | 304/3613 = 8.41% | 211/2044 = 10.32% |
| FireRedASR2 CTC INT8，VAD 仅门控 | 383/3613 = 10.60% | 544/2044 = 26.61% |

因此常驻服务默认选“VAD 门控 + 整段识别 + ITN 开”。门控与完全不用 VAD 在这批有语音样本上输出相同，但门控避免纯静音被误转写。切段识别的英文词错误比门控多 66 个，可能与语音边界处丢失上下文有关。FireRedASR2 CTC INT8 在本批样本上未降低错误率，不切换正式服务。100/99 条样本仍不能代表实际麦克风、方言或专业术语场景；主要困难样本包含专名、地名及中英混说。不同配置的测试与下载任务曾并发，表中的准确率可比，延迟需在空闲机器上再测。

FireRed 对照的每段平均服务处理时间：中文 4252 ms、英文 2953 ms；对应 SenseVoice 门控约 553 ms 和 469 ms。FireRed 临时服务模型加载后 RSS 约 950 MiB，处理长音频后峰值约 1273 MiB。它与 SenseVoice 测试时系统负载未严格一致，延迟和内存只用于当前虚拟机的选型参考。原始对照在 `output/evaluation/fleurs_zh-en_100_gate_firered.json`；临时服务已停止。

## 公开录音上的 STT

SenseVoice INT8，2 线程，预热 1 次、统计 7 次。官方模型包中的中文音频长 5.592 秒，英文长 7.152 秒。CER/WER 仅基于各 1 条标注语音。

| 语音 | 无 VAD 推理均值 / RTF | 开 VAD 推理均值 / RTF | 错误率 | 识别中的明显错误 |
| --- | ---: | ---: | ---: | --- |
| 中文 | 283 ms / 0.051 | 215 ms / 0.038 | CER 1/13 = 7.69% | “开放”成“开饭” |
| 英文 | 364 ms / 0.051 | 258 ms / 0.036 | WER 1/15 = 6.67% | “gold”成“code” |

此处 VAD 把较短的语音段交给 STT，因此表中推理时间降低；VAD 自身约 26 ms（中文）和 33 ms（英文），加载约 8～10 ms，均未计入该推理数字。两次评测在不同时间运行，性能差异也可能受系统负载影响。峰值 RSS 约 334～337 MiB。

纯静音 1 秒：不启用 VAD 时识别出无关文本 `그.`；启用 VAD 时输出空文本、0 个语音片段，VAD 处理约 3.8 ms。20/10 dB 固定高斯噪声下，中文无 VAD 的 CER 均为 7.69%，带 VAD 的 20 dB 样本上升到 15.38%；英文 20 dB 的 WER 为 0，10 dB 为 13.33%。这些单条样本不能代表总体鲁棒性；尤其不能据此声称 VAD 总能提升准确率。

## 线程扫描

同一中文 STT 音频和同一短中文 TTS 文本；各配置在独立进程中运行。TTS 为 Kokoro INT8。

| CPU 线程 | STT 平均 / RTF | Kokoro TTS 平均 / RTF |
| ---: | ---: | ---: |
| 1 | 422 ms / 0.075 | 4531 ms / 1.782 |
| 2 | 244 ms / 0.044 | 4407 ms / 1.734 |
| 4 | 178 ms / 0.032 | 3588 ms / 1.407 |

这是单请求结果。4 线程在这台 VM 上最快，但并发请求时需要重新扫描线程数。Kokoro 在这台 VM 上的 RTF 大于 1。

## 相同短句的 TTS 对比

每项 4 线程，预热 1 次、统计 5 次；生成的最后一个 WAV 用 STT+VAD 回读。中文文本为“你好，欢迎使用语音服务。”；英文文本为 “Welcome to the offline speech system.”。不同模型产生的音频时长不同，故同时报告绝对延迟和 RTF。

| 语言与后端 | 音频时长 | 合成均值 / P95 | RTF | 峰值 RSS | 回读 |
| --- | ---: | ---: | ---: | ---: | --- |
| 中文 Kokoro INT8 | 2.554 s | 3536 / 3679 ms | 1.385 | 355 MiB | 完全一致 |
| 中文 Piper | 2.620 s | 187 / 201 ms | 0.072 | 198 MiB | 完全一致 |
| 英文 Kokoro INT8 | 2.086 s | 2747 / 3003 ms | 1.317 | 361 MiB | 完全一致 |
| 英文 Piper | 2.125 s | 110 / 117 ms | 0.052 | 146 MiB | “Welcome”回读为“Come”（WER 1/6） |

四段音频均无达到 16-bit 上限的样本，RMS 电平约 -19 至 -27 dBFS。另一轮英文 Piper 合成回读曾完全正确，说明短句与随机合成结果存在波动；没有听测或 MOS/主观音质结论。实际产品的默认音色应结合真实语料和听测确定。

报告原始 JSON：`output/evaluation/report.json`、`output/evaluation/report_vad.json`、`output/thread_sweep/report.json`、`output/evaluation/tts_compare.json`。`scripts/evaluate.py`、`scripts/thread_sweep.py`、`scripts/tts_compare.py` 可在 VM 重跑。报告中的 P95 只来自 3～7 次重复；若做服务等级指标，需增加样本数、文本长度分布和并发压力。
